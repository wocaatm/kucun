# 小库存

代购小生意的进销存 + 记账手机网页：扫码出入库、拍小票 AI 识别、合伙人垫付与结算、利润看板。

## 结构

- `server/`：Fastify + Node 内置 SQLite（`node:sqlite`），直接运行 TypeScript（Node ≥ 22.18）
- `web/`：React + Vite + antd-mobile，打包后由 server 直接提供

## 本地开发

```bash
cd server && cp .env.example .env   # 填 VISION_API_KEY
npm install && npm run dev          # http://127.0.0.1:3100
cd ../web && npm install && npm run dev   # http://localhost:5173，/api 代理到 3100
```

测试：`cd server && npm test`

## 线上

- 地址：https://kucun.kidslearnenglish.xyz
- 服务器 `/opt/kucun`：代码 `server/`、前端 `web/dist`、数据 `data/`（数据库、图片、每日备份）
- 进程：pm2 `kucun`（`/opt/kucun/ecosystem.config.cjs`，127.0.0.1:3100，内存超 260M 自动重启）
- nginx：`/www/server/panel/vhost/nginx/kucun.kidslearnenglish.xyz.conf`（宝塔目录）
- 证书：certbot，`/etc/cron.d/kucun-cert` 每天检查续期
- 发版：`./deploy.sh`

## 部署（从零）

```bash
cd web && npm run build                  # 产物在 web/dist
cd ../server && npm start                # 同时提供 API 和 web/dist
```

- 环境变量见 `server/.env.example`；`DATA_DIR` 下是数据库 `kucun.db`、图片 `uploads/`、每日备份 `backups/`
- 扫码需要 HTTPS（摄像头权限），用 nginx 反代到 3100 并配证书

## 业务规则（摘要）

- 金额一律以「分」存储
- 账户：公共资金 + 每人一个个人账户。个人账户负数 = 此人垫付待还，正数 = 代收待交
- 成本：移动加权平均，按单据日期（同一天按录入顺序）重放；允许负库存（先卖后买），进货后自动补成本。补录早日期的进货或改单据日期，之后的卖出成本会跟着重算
- 涉及金额 / 库存的单据只能作废，不能修改删除；作废后重放，库存与成本自动回滚
- 利润 = 销售额（含淘宝邮费，扣退款）− 卖出成本（扣退回入库成本）− 支出 − 损耗/自用/盘亏 + 其他收入；分成比例在 `server/src/settings.ts`
- 商品详情有进货记录：每次进货的日期、件数、实付单价（优惠 / 运费已摊入）、付款人
- 进价 = 实付：进货单上的运费、包装费、优惠券等按商品标价比例摊进每行成本（`doc_items.in_cost`），商品均价和库存价值都按实付算，不再单独算支出或优惠。等式：利润 = 计入的销售额 − 花的钱（进货实付 + 支出）+ 库存成本
- 退货退款：只能从原销售单发起，按行填退回件数（0 = 仅退款）、退款金额、退回入库成本（默认原卖出成本），利润减少 = 退款 − 退回成本
- 识别：OpenAI 兼容接口（默认 DeepSeek `deepseek-flash`），换模型只改环境变量
- 参考商品库（`catalog_items`）：奥乐齐全量商品与「一级/二级」类目，不含价格、不进库存；扫码 / 搜商品 / 识别小票时查询，选中或提交单据时才建档（`products.source/source_id` 关联）。同步：`cd server && npm run sync:aldi`，或页面「我的 → 奥乐齐商品库 → 同步」
- 商品匹配顺序：条码 → 商家货号 → 记住的小票名称 → 名称相似度（含淘宝长标题）→ 参考库

## 淘宝订单

每天从千牛导出「订单列表」两张表（主订单表 + 子订单表，全部字段），在「我的 → 淘宝订单导入」上传，或 `cd server && npm run import:taobao -- a.xlsx b.xlsx [--dry]`。按订单号幂等，重复导入安全；原始文件留档在 `data/imports/taobao/`。

- 子订单有发货时间 → 生成销售单（按主订单），全额计入销售额；钱记公共资金但标「待到账」，汇总为淘宝应收（发货超 10 天标红）
- 按 SKU 行算：能确定的商品扣库存、计入销售额和成本；确定不了的行（SKU 没对照 / 自动匹配未确认 / 有商家备注未核对实发）只记金额、标「未匹配 / 待核对实发」，不建商品、不扣库存，暂不计入销售额和成本（应收照样全额），首页营业额处提示；补上后自动作废旧单、按原日期和到账状态重建并计入
- 主订单交易成功 → 销售单标已到账，计入公共资金余额
- 发货后退款成功 → 自动生成「待处理退款」（默认仅退款），在单据里确认「货退回来了 / 仅退款」
- 没发货就关闭或退款的不生成单据；买家已付款待发货的列在「待发货」
- SKU（商品ID + 规格）对照到库存商品（套装可对多个），自动匹配的要人工确认才生效
- 实发：每个订单都可以在「淘宝订单 → 订单 → 订单详情」随时改实际发出的商品（空包、改发别的、加赠品），待发货的也能先填好；改完已生成的销售单按新实发重建，销售额仍按买家实付全额，按商品参考价比例分摊。有商家备注的订单要先核对实发（或确认「按下单发」）才扣库存。货已经退回来的订单不能改实发，要先作废那张退货单；只退了钱的，退款转成不关联商品的金额。每次修改都有记录
- 邮费 = 主订单实付 − 子订单实付合计，作为销售单的「邮费」计入销售额
- 淘宝导入的单据不能手动作废，也不能改日期
- 刷单：不单独标记。刷手付的钱照常算淘宝销售额、进公共资金；给刷手私下发的红包，由发的人从自己的账户记支出「刷单」（算垫付，公共资金还他）；寄出的东西在订单详情里改实发（空包就选「空包」）
- 单据可改的只有备注、图片、日期（非淘宝单）和支出 / 收入分类，都不影响金额；改日期会按新日期重算成本
